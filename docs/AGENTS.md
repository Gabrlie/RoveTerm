# docs/AGENTS.md：文档规范

本文定义文档分层、写作规则和字数上限。字数上限由 `node scripts/check-docs.mjs` 检查。

## 文档结构

每篇文档的主题和它在目录树中的位置决定了它的范围：只详细描述自己的主题，对子级只说明用途与职责，更细的内容链接到子级文档。

每篇文档归为**教程**或**参考**两类之一。教程按步骤带读者达成一个结果，每一步只引入当下需要的概念；参考描述某个范围内的当前行为，不安排教学顺序。两类内容较多时分开成两篇；较少时用小节标明。

## 分层：每个事实只有一个归宿

每个事实只写在它所属的那一层，其他地方链接过去。

| 层 | 职责 | 不放这里 |
|---|---|---|
| 根 `AGENTS.md` | 常驻规则：每次会话都需要的规则，每条 1–3 行，链接归宿 | 故事、示例、情境化流程、对链接文档的复述 |
| [architecture.md](architecture.md) | 有序地图：内核、Profile、核心 crate、事件、会话数据流、seam、扩展点归属 | 类型定义（→ subsystems）、单 crate 细节（→ crate README）、决策理由（→ decisions） |
| [subsystems/](subsystems/README.md) | 每个子系统一页参考：类型、语义、不变量 | 行为叙述（→ architecture.md） |
| [decisions/](decisions/README.md) | 决策记录：为什么、放弃了什么、需要怎样验证 | 实施清单、迁移计划 |
| [defensive-patterns/](defensive-patterns/README.md) | 评审时强制执行的规则，按领域分页 | 类型语义、决策理由 |
| [cookbook/](cookbook/README.md) | 带编号验证步骤的分步指南 | 设计理由（→ 链接到决策记录） |
| [security.md](security.md) | 威胁模型、密钥层级、信任边界 | 具体实现细节（→ subsystems） |
| [testing.md](testing.md) | 测试分层、工具、性能基线 | 单个测试的说明 |
| [development.md](development.md) | 环境搭建、日常流程、CI 概要 | 会与 `package.json` / `Cargo.toml` 脱节的逐条命令清单 |
| crate `README.md` | 单个 crate 的契约：配置、语义、局限、扩展点 | `///` 注释的复述、其他 crate 的事务 |

放置规则：理由 → decisions；流程 → cookbook；类型 → subsystems；crate 契约 → README；常驻规则 → 根 `AGENTS.md`；评审规则 → defensive-patterns。

## 写作规则

- **只写当前状态**。历史留在提交记录和决策记录里；不写"已实现！""未来：……"这类状态标注。
- **一个段落占一行物理行**，依赖编辑器软换行；代码块、表格、列表保持原格式。
- **注释和 `///` 文档写完整契约**：行为、失败、时机、所有权、安全用法；删掉推理过程、测试走查和对代码的复述。
- **直接写**：说出执行者和事实，用准确的类型名、API 名、操作名，不用比喻。`seam` 只用于[术语表](glossary.md#seam)定义的含义。
- **强调要克制**：只给改变行为的那个子句加粗。
- 文档以中文为主；代码标识符、协议名、命令保持原文。

## 字数上限

上限定义在 [scripts/doc-budgets.json](../scripts/doc-budgets.json)，统计方式为中文字符数 + 英文单词数。检查失败时：

1. **迁移**：把属于其他层的内容挪过去，必要时留一行链接。
2. **压缩**：属于本层但可以更短的内容。
3. **提高上限**：只在内容确实需要时才提高，并在提交说明里写明理由。

## 冗余检查清单

- 重复规则：搜索一个有辨识度的短语，只保留一处，其他改为链接。
- 出现在不该出现位置的历史叙述。
- 散文或图表里的实现状态标注。
- 手工复述源码已经权威表达的内容（类型清单、测试清单）。
- 推理过程：逐步实现叙述、对显然分支的论证、被否决的局部方案。
- 段落墙：一段承载多条规则和括号旁注时，拆开或把细节挪到归宿。
