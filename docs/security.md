# 安全模型

本文描述 RoveTerm 保护的资产、信任边界和密钥层级。各子系统的实现细节见对应的 [subsystems](subsystems/README.md) 页面。

## 资产

- 主机凭据：密码、私钥、私钥 passphrase。
- 同步与 AI 服务的 token、API key。
- 终端内容和 AI 的操作记录。
- 目标服务器本身：错误放行的命令可能破坏远程主机。

## 信任边界

| 来源 | 信任程度 | 处理方式 |
|---|---|---|
| 同进程内的类型化调用 | 信任 | 依赖类型系统，不重复做运行时校验 |
| WebView 发来的 IPC 参数 | 不信任 | 在 Tauri 命令处校验 ID、尺寸、长度 |
| 远程 SSH 服务器 | 不信任 | 首次连接校验 host key，指纹变化时拒绝连接 |
| Tailscale CLI 输出 | 不信任 | 限制运行时间与输出大小，校验状态、设备 ID 和 IP 地址，仅返回设备摘要 |
| Agent 子进程（ACP） | 不信任 | 校验路径、大小、枚举；它的权限请求不参与决策；环境变量按白名单传入 |
| MCP 桥接连接 | 不信任 | 只监听回环地址；先校验每会话随机生成、只在内存中的 256 位 token（经环境变量而非命令行传给桥接进程）；工具调用与 ACP 请求走同一审批 |
| 同步后端 | 不信任 | 只接收密文；无法读出明文，也无法伪造记录 |

## 密钥层级

```
系统钥匙串 / Android Keystore
  └─ 设备主密钥（随机 32 字节，每台设备一把）
       └─ HKDF → vault 加密密钥 → XChaCha20-Poly1305 按字段加密凭据（AAD 绑定记录 ID 与字段名）

用户的同步密码
  └─ Argon2id → 同步密钥 → 密封离开本机的数据（同步分段、导出包）
```

- 设备主密钥从不离开本机，不参与同步和备份。
- 同步密码本身从不持久化；导入到新设备时，凭据用新设备的主密钥重新加密。
- 内存中的密钥类型实现 `Zeroize`，drop 时清零。

## 解锁

- 启动时静默尝试从钥匙串读取设备主密钥，不弹出授权。
- 读取失败时 vault 保持锁定，应用照常可用：主机列表等元数据可读，凭据不可读。
- 只有用户发起的、需要凭据的操作才会请求解锁；用户取消时保留已填写的内容。
- 生产环境没有内存或明文文件形式的主密钥后备方案。

## SSH

- known_hosts 由 vault 维护。首次连接时把指纹交给用户确认；已记录的指纹变化时拒绝连接，并提示可能存在中间人攻击。
- 凭据只在建立连接时解密，用完即清零。
- 端口转发的本地监听地址只接受 IP 地址或 `localhost`，默认 `127.0.0.1`；监听非回环地址会把转发开放给局域网中的其他机器，UI 对此给出提示。动态转发的 SOCKS5 代理不做认证，不应监听非回环地址。

## 同步与备份

- 每台设备只向后端写入自己的分段，不覆盖其他设备的文件；清理时也只删除自己的分段。
- 同步内容不包括：设备主密钥、本机 MCP token、同步后端自身的凭据、本机 SSH 密钥与主机的对应关系。

## 文件编辑

外部编辑器由用户按设备配置，经独立参数启动，不通过 shell。编辑器读取应用数据目录下的本机明文副本，副本不参与同步、不受 vault 字段加密保护；Unix 目录与初始文件权限分别为 `0700` 和 `0600`，Windows 依赖用户数据目录的访问控制。副本保留与写回规则见 [文件编辑](subsystems/fs.md#文本编辑)。

## Tailscale 发现

桌面端只使用本机 CLI 的固定参数 `status --json` 读取设备，不经 shell，不获取 Tailscale token，也不发起登录或更改组网。设备摘要不包含登录 URL 和账户清单；发现状态不授予远端操作权限，后续连接仍经既有 SSH 认证、host key 校验和 AI 审批。接口边界见 [tailscale](subsystems/tailscale.md)。

## AI

- 权限模式分为询问、审阅、自动三种；`Dangerous` 级别的命令始终需要人工确认。
- 命令风险分级时，不认识的命令按 `Modify` 分级，交给当前审批策略处理。
- Agent 子进程的环境变量采用白名单，剥离 `SSH_AUTH_SOCK` 和云厂商凭据变量。
- AI 执行过的命令、读写过的文件、审批结果都写入 Journal。
- 持久运维任务冻结目标主机及连接身份，实际操作权限取任务范围与实时 Policy 的交集。交互任务遵循实时审批模式，`Dangerous` 操作始终需要人工确认；无人值守的定时任务默认只读，启用 `schedule.allow_changes` 后才允许审阅者放行修改。只读任务的 `AiSession::restrict_read_only` 约束在 `set_mode`、会话授权和审阅之后仍生效。
- 运维任务的输入、工具正文、报告和检查点密封到本机 `ops/private` 审计，任务元数据保存状态及 `PrivateRef`。私有正文与检查点不参与同步，执行队列归属于当前设备；同步对话不会转移执行权。
- 未知的远端修改先保留为待核对状态，用户核对服务器后明确确认才允许继续；模型追加输入不能自动解除该状态。应用重启只恢复任务状态，旧的一次性审批不重复使用。恢复边界见 [ops](subsystems/ops.md#恢复和跟进)。

## 日志

日志、错误信息和 Journal 事件中不写入任何凭据明文。

无人值守（定时任务）时没有人回答审批：只读操作执行，修改只在判断者确信时执行，其余修改与所有危险操作一律拒绝，并列入报告的"需要你决定"，从不因等待审批而挂起。任务未开启"允许修改"（默认）时不设判断者，所有修改都被拒绝；定时任务仅在指定设备的应用运行期间执行。敏感文件读取需用户决定，shell 的命令级会话授权不能放行此类读取。

开放给本机智能体（默认关闭）时，`mcp.json` 中的 token 允许本机任何能以当前用户身份读取该文件的进程经回环端口使用已保存的主机；所有操作仍经审批模式、规则与审阅者，并记入 Journal，凭据不离开 vault。关闭开关即删除文件并停止监听。

自动模式的判断者选 Jev 时，待判断操作的描述（主机名、命令或文件路径与改动、风险原因）会发送给 TypeSafe 的服务；选模型（对话所用的或指定的）时发送给该模型服务商。两者都不含文件全文与凭据。

日志同时输出到终端和数据目录下的 `logs/roveterm.YYYY-MM-DD.log`（按天滚动，保留 7 个文件），供用户反馈问题时发送；界面的 `console.warn` / `console.error` 与未捕获错误经 `log_write` 转发进同一日志（每条最多 4 KiB，每分钟最多 60 条）。代码只记 id 与状态，不记密码、私钥、API key 或 token。
