# ops

`rove-ops` 将用户请求和定时请求表示为持久任务，并为模型 worker 提供共享调度。配置和状态迁移契约见 [crate README](../../crates/rove-ops/README.md)。

## 角色

| 角色 | 实现 |
|---|---|
| Definition | `TaskStore`、`OpsTask`、`OpsSubtask`、授权范围、worker 结果 |
| Provider | `JournalTaskStore`、`OpsSupervisor`，由 `OpsPlugin` 注册 |
| Consumer | 应用中的运维 worker 适配器、任务 IPC、总管和定时调度 |

## 数据流

调用方先将输入正文密封到本机私有审计存储，再使用 `PrivateRef` 创建任务。Supervisor 验证来源标识和冻结的主机范围，持久保存元数据后允许派发；元数据事件为 `ops/task_event`。同一来源重试复用原任务。

交互新任务允许修改，每项操作遵循实时 `Policy`（`ask_all` / `ask_by_risk` / `auto`）。无人值守的定时任务默认只读，仅启用 `schedule.allow_changes` 后才允许审阅者放行修改；`TaskScope.can_modify` 保留任务范围，历史只读任务在跟进时仍保持只读。

每个目标主机对应一个子任务。执行器先取得 `WorkerLease`，再启动或恢复该子任务的模型会话；不同入口共享全局许可。任务路由器可持有 `TaskRunGuard`，防止同一任务出现两个并行的派发器。

worker 的审批等待、检查点、效果回执和结束原因分别写入任务。运维元数据只保存正文引用。任务 IPC 与 `ops-update` 提供标题、状态计数和主机结果。正文无法解密时，视图仍显示主机与状态。

总管可为任务提供标题和验收项。worker 将答复和操作计数写入加密报告，视图也能读取早期报告中的逐项验收结果。正常回合可以凭答复完成。没有成功操作且有审批拒绝时记为受阻，只有失败操作且无答复时记为失败。未确认的远端效果仍需核对。

交互任务的全部目标进入终态后，Supervisor 通知当前总管汇总。总管忙时合并待汇总任务，按任务 ID 和修订号去重。汇总回合只开放读取工具。

## 恢复和跟进

重启只恢复状态，不派发命令。中断的远端修改先核对实际结果，不能凭一次模型回合的重试重复执行。失去 worker 的待审批项转为受阻状态，用户明确继续后才重新请求审批。

总管恢复时会关闭旧未决工具调用并读取当前持久任务状态，以便继续已有任务。用户可以按主机或整个任务重试，也可以按主机、任务或对话取消。

用户追加输入后，由 Consumer 明确选择需要继续的子任务；已完成主机不会因另一个主机失败而重跑。重试和跟进复用子任务 ID、模型会话和检查点引用，验收证据属于本次执行结果。任务目标可打开对应的子代理会话。
