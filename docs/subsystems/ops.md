# ops

`rove-ops` 将用户请求和定时请求表示为持久任务，并为模型 worker 提供共享调度。配置和状态迁移契约见 [crate README](../../crates/rove-ops/README.md)。

## 角色

| 角色 | 实现 |
|---|---|
| Definition | `TaskStore`、`OpsTask`、`OpsSubtask`、授权范围、worker 结果 |
| Provider | `JournalTaskStore`、`OpsSupervisor`，由 `OpsPlugin` 注册 |
| Consumer | 应用中的运维 worker 适配器、任务 IPC、总管和定时调度 |

## 数据流

调用方先将输入正文密封到本机私有审计存储，再使用 `PrivateRef` 创建任务。Supervisor 验证来源标识和冻结的主机范围，持久保存元数据后允许派发；元数据事件为 `ops/task_event`。同一来源重试复用原任务。

交互新任务允许修改，每项操作遵循实时 `Policy`（`ask_all` / `ask_by_risk` / `auto`），`Dangerous` 操作始终需要人工确认。无人值守的定时任务默认只读，仅启用 `schedule.allow_changes` 后才允许审阅者放行修改；`TaskScope.can_modify` 保留任务范围，历史只读任务在跟进时仍保持只读。

每个目标主机对应一个子任务。执行器先取得 `WorkerLease`，再启动或恢复该子任务的模型会话；不同入口共享全局许可。任务路由器可持有 `TaskRunGuard`，防止同一任务出现两个并行的派发器。

worker 的审批等待、检查点、效果回执和结束原因分别写入任务。存储只保存引用，不接收模型提示、命令输出或报告全文。界面从引用的加密正文读取报告及验收证据。

应用 Consumer 要求模型通过 `submit_result` 逐项提交验收结果，并引用本轮真实成功操作的证据 ID；未覆盖全部验收项时，普通回合结束记为受阻。较早的诊断失败或拒绝保留在报告中，完成状态取决于后续已验证结果及是否仍有未确认效果。

## 恢复和跟进

重启只恢复状态，不派发命令。中断的远端修改先核对实际结果，不能凭一次模型回合的重试重复执行。失去 worker 的待审批项转为受阻状态，用户明确继续后才重新请求审批。

总管存在未完成的检查点时，用户先查看持久任务和证据，再明确确认恢复；恢复会补入当前任务状态并替换旧未决调用，原始输入由用户手动重试。

用户追加输入后，由 Consumer 明确选择需要继续的子任务；已完成主机不会因另一个主机失败而重跑。继续保留原有子任务 ID、模型会话和检查点引用，验收证据属于本次执行结果。
