# 测试

## 原则

- **只测逻辑**：测试持久化数据、加解密、解锁、连接、发送或拦截的命令、错误和安全检查；不写截图、像素、布局、颜色类 UI 测试。只改 UI 外观的改动不需要测试。
- **按影响范围测试**：代码改动后只跑受影响 crate 的相关测试（`cargo test -p <crate> <filter>`）。全量测试和跨平台矩阵交给 CI。
- **纯文档改动不跑测试**，运行 `node scripts/check-docs.mjs` 并审阅文档 diff。
- 测试描述行为。行为改变时，连同测试一起修改。

## 分层

| 层 | 位置 | 说明 |
|---|---|---|
| 单元测试 | 各 crate 的 `#[cfg(test)]` 模块 | 不依赖网络和系统钥匙串 |
| 集成测试 | 各 crate 的 `tests/` | SSH 相关测试连接进程内启动的 [devsshd](../tools/devsshd/README.md) |
| 手工端到端 | `pnpm tauri dev` | 按下方清单逐项确认 |

需要系统钥匙串的测试用 `KeyCache` 的内存实现代替；该实现只在测试和 `dev` 构建中可用。

## 手工端到端清单

1. 本地终端运行 `htop`、`vim`，确认全屏界面、颜色和窗口缩放正常。
2. 运行 `yes | head -n 2000000`，确认界面不卡顿、输入仍能及时响应。
3. 打开 4 个分屏连接同一台主机，确认只建立了一条 TCP 连接（`ss -tnp` 查看）。
4. 在终端里按 Ctrl+C、Ctrl+R 等组合键，确认它们到达 shell，而不是被应用截获。
5. 重启应用，确认静默解锁成功，主机列表和凭据可用。

## 性能基线

在 release 构建上测量，结果记录在下表。

| 指标 | 目标 | 测量方法 |
|---|---|---|
| 空闲内存（桌面） | < 120 MB | 启动后打开一个本地终端，静置 10 秒，统计进程树的 RSS 总和 |
| 冷启动 | < 500 ms | 从进程启动到第一个终端可输入 |
| 安装包体积 | 尽量小 | `pnpm tauri build` 产物大小 |

### 当前测量结果

测量环境：Linux x86_64，Xvfb 软件渲染（无 GPU），WebKitGTK 2.52，release 构建（`pnpm tauri build --no-bundle`），在 `dbus-run-session` 内运行，打开一个本地终端，三次取平均。

| 指标 | 结果 | 是否达标 |
|---|---|---|
| 可执行文件体积 | 9.4 MB | — |
| 进程启动到第一个 shell 启动 | 约 1.1 s（含测量脚本 0.3 s 的等待） | 未达标 |
| 空闲 RSS 总和 | 约 370 MB：主进程 147 MB、WebKitWebProcess 172 MB、WebKitNetworkProcess 49 MB、bash 10 MB | 未达标 |

- 没有 D-Bus 会话总线时，GTK / WebKit 的 D-Bus 连接会超时，启动时间超过 30 s；正常桌面会话不受影响。
- 软件渲染会抬高主进程和 WebProcess 的内存，真实桌面需要重新测量；内存优化（共享 WebProcess、关闭不需要的 WebKit 功能、减少 scrollback）是后续工作。
