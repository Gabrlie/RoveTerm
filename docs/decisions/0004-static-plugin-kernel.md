# 0004：静态链接的插件内核

## 背景

参考 deepseek-harness "一切皆插件" 的架构：能力可以替换，扩展不需要修改内核。RoveTerm 同时追求低内存和快速启动。

## 决定

- `rove-kernel` 提供类型化服务注册表、事件总线和 `Disposer`；每个插件在 `apply` 中注册服务，卸载时撤销。
- 插件在编译期静态链接，由 profile 选择启用哪些。
- 进程外扩展通过 MCP / ACP 接入。

## 放弃的方案

- **动态库插件**：Rust 没有稳定 ABI，跨平台分发和签名复杂。
- **WASM 插件运行时**：增加体积和启动时间；当前没有需要进程内第三方代码的场景。
- **不设内核、模块直接互相调用**：替换某项能力（例如钥匙串后端、同步后端）时需要修改调用方。

## 代价

- 第三方无法在不重新编译的情况下添加进程内插件。
- 服务通过 `TypeId` 查找，错误的注册顺序只能在运行时发现，因此 `Runtime` 在启动时检查插件依赖。

## 验证

kernel 的单元测试覆盖：Disposer 撤销注册、重复注册报错、waterfall 不调用 `next` 时短路、插件依赖缺失时启动失败。
