# 0006：通过 ACP 接入外部 Agent，由本地 Policy 审批每一步

## 背景

用户希望在终端里与 AI Agent（首先是 Codex）协作：让它看到终端内容、读写文件、执行命令，并且作用于当前聚焦的主机——可能是本机，也可能是经 SSH 连接的远程服务器。Agent 是第三方程序，它的输出和请求都不可信；它执行的每一步都可能修改服务器，必须经过用户可控的审批，并能在事后完整还原。

## 决定

- **ACP 客户端**：RoveTerm 以子进程启动 Agent（Codex 经 `codex-acp` 适配器），通过 stdio 上的 JSON-RPC 使用 Agent Client Protocol 通信。RoveTerm 是客户端：发起会话与提示，接收流式更新，响应 Agent 的请求。Agent 的环境变量按白名单组装，API key 从 vault 解密后只放进 Agent 的环境。
- **主机上下文**：每个 AI 会话绑定一个主机上下文（本机或某台已保存主机）。Agent 能用的文件与命令操作都在这台主机上执行：远程主机复用应用已有的共享 SSH 连接，用 exec 通道运行命令、SFTP 读写文件，不自行发起新连接或询问密码。
- **两条通道**：RoveTerm 同时向 Agent 提供 ACP 的 `fs/*`、`terminal/*` 客户端能力，以及一个内置的 MCP server（运行命令、读写文件、列目录、读取终端内容）。Agent 是否使用客户端能力由它自己决定；MCP 工具是任何支持 MCP 的 Agent 都能使用的通道。MCP server 由应用二进制以桥接模式启动，经本机 socket 连回运行中的应用，并用每会话随机生成、不落盘的 token 认证。
- **Policy**：两条通道上的每个操作，以及 Agent 为自带工具发来的权限请求，都交给本地 `Policy` 决定。命令按 shell 语法拆分，各段分为只读、修改、危险三级，取最高级；文件读取为只读，写入为修改，写入系统路径为危险。三种模式：按风险询问（默认，只读自动放行）、全部询问、自动（危险仍询问）。用户可以在会话内允许同一主机、同一程序的修改级操作；危险级每次都要确认。Agent 自己提出的"始终允许"选项不参与决策。
- **审计**：AI 会话的提示、回复、工具调用、审批结果、执行的命令及其输出、读写过的文件都写入 Journal（`ai/*` 事件），输出与内容按上限截断并记录截断标记、内容哈希，能从日志还原 AI 做过的每一步。

## 放弃的方案

- **只用 Agent 自带的工具**：Agent 的工具在本机执行，无法作用于远程主机，审批也由 Agent 自己决定。
- **应用内直接调用模型 API**：需要自己实现 Agent 循环与工具调度，也无法复用用户已登录的 Agent。
- **把 Agent 的权限请求直接展示给用户**：Agent 能提供"始终允许"等选项绕过审批；风险由本地判断才可控。

## 代价

- 命令分级是启发式：混淆写法可能被判为较低级别，因此未识别的命令一律视为修改级，不会自动放行。
- 依赖外部 Agent 程序与其 ACP 适配器的行为；适配器不使用客户端能力时，远程操作只能通过 MCP 工具完成。
- 截断后的输出无法在审计中完整还原，只保留哈希与截断标记。

## 验证

`rove-ai` 的测试覆盖：命令分级表（管道、子 shell、引号拼接等写法）；三种模式下的放行与询问；用假 Agent 走完整的 ACP 往返，被拒绝的操作向 Agent 返回错误；MCP 桥接的往返与错误 token；远程主机上的命令与文件操作（devsshd）；Journal 能还原一整轮操作。
