# 0003：设备主密钥 + 字段级加密的凭据存储

## 背景

凭据必须加密存储，同时日常使用不应每次都要求输入主密码。凭据还需要能在多设备之间安全同步。

## 决定

- 每台设备随机生成 32 字节的设备主密钥，只存放在系统钥匙串（Android 为 Keystore）中。
- 凭据按字段用 XChaCha20-Poly1305 加密存入 SQLite；加密密钥由设备主密钥经 HKDF 派生；AAD 绑定记录 ID 与字段名，防止密文在记录之间被挪用。
- 启动时静默读取主密钥；读取失败时应用照常可用，只有需要凭据的操作才请求授权。
- 同步和导出使用另一把由用户同步密码经 Argon2id 派生的密钥；设备主密钥从不离开本机。

## 放弃的方案

- **主密码派生 vault 密钥**：每次启动都要输入密码，体验差；密码强度直接决定本地安全性。
- **SQLCipher 整库加密**：需要额外的 C 依赖和构建配置；主机名等元数据并不敏感，按字段加密已经足够。

## 代价

- 安全性依赖系统钥匙串；Linux 上需要可用的 Secret Service。
- 字段级加密不隐藏主机名、用户名等元数据。

## 验证

单元测试覆盖加解密往返、AAD 不匹配时解密失败、钥匙串不可用时保持锁定且不报错。
