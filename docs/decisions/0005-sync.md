# 0005：每台设备只追加自己分段的端到端加密同步

## 背景

主机、密钥库、快捷指令、端口转发和偏好需要在多台设备之间同步，后端可能是 WebDAV、S3、Gist 或一个本地同步文件夹（iCloud、Dropbox、Syncthing）。这些后端大多是"哑"存储：没有事务，也没有条件写入，两台设备同时写同一个文件时会互相覆盖。后端也不可信：它不应读到任何明文，也不能伪造或悄悄改写记录。

## 决定

- **空间**：一个同步空间对应后端的一个目录。第一台设备写入 `space.json`：KDF 参数、随机盐，以及用同步密钥密封的固定校验串。其他设备用同一个同步密码派生密钥，能打开校验串即密码正确。
- **密钥**：同步密码经 Argon2id（64 MiB、3 轮、1 线程，盐 16 字节）派生 32 字节同步密钥。数据用 XChaCha20-Poly1305 密封，AAD 绑定文件用途和位置（设备 id、分段序号），后端无法挪用、改名或伪造分段。派生出的同步密钥用本机设备主密钥加密后存在 vault 中，免得每次同步都输入密码；同步密码本身从不保存。
- **分段**：每台设备只写 `devices/<设备 id>/<序号>.seg`，序号递增、写后不改。一个分段是一批变更，每条变更为（记录类型，记录 id，HLC 时间戳，内容或删除标记）。写冲突因此不可能发生；清理时设备也只删除自己的分段。
- **合并**：每条记录按混合逻辑时钟（HLC：毫秒时间、计数器、设备 id）比较，后写者胜（LWW）；删除以墓碑表示，同样参与比较。设备加入空间的第一轮例外：双方都有的记录以空间为准。设备记下每台其他设备已读到的序号，只拉取新分段。
- **变更检测**：同步时把本地记录与上次同步时的指纹逐条比较，得出新增、修改和删除，不要求每个写操作都记录变更。指纹用同步密钥派生的 HMAC 计算，凭据明文不会以可离线猜测的形式留在本地。
- **同步内容**：主机（含凭据）、密钥库（含私钥）、快捷指令、端口转发规则、随用户走的偏好。不同步：设备主密钥、本机偏好（`DevicePrefs`）、known_hosts、同步后端自身的凭据。凭据到达新设备后用该设备的主密钥重新加密存储。

## 放弃的方案

- **单个共享状态文件**：哑存储上并发写会丢数据，且每次都要上传全部内容。
- **由服务端合并**：需要可信的服务端，并让服务端看到明文，或需要更复杂的协议。
- **在每个写操作处记录变更**：要改动所有写路径，遗漏一处就会丢同步；指纹比较只依赖读接口。

## 代价

- 后端可以删除或扣留分段，造成某些变更缺失，但无法伪造或篡改；这是端到端加密的已知限制。
- 分段持续增加，各设备在自己的分段超过一定数量时压缩自己的历史；压缩前已离线很久的设备仍能读到结果，因为压缩后的分段包含每条记录的最新状态。
- LWW 不合并同一记录的并发编辑：较晚的一方覆盖较早的一方。

## 验证

`rove-sync` 的测试覆盖：错误的同步密码被拒绝；被篡改或挪用的分段无法打开；两台设备经同一后端交换变更后状态一致；并发修改同一记录时 HLC 较大者胜；删除可以传播且不会被旧修改复活。
