# 防御性规则

评审时强制执行的规则。修改并发与关闭逻辑、密钥处理或 IPC 命令之前先读本页。

## 并发与关闭

- 每个后台任务都有明确的所有者；所有者 drop 时任务必须结束（通过 `CancellationToken` 或关闭 channel），不留孤儿任务。
- 关闭会话时，先停止读取再释放底层资源；关闭操作可以重复调用且保持幂等。
- 不在持有 `std::sync::Mutex` 的情况下 `.await`；需要跨 await 持锁时使用 `tokio::sync::Mutex`，并尽量缩短持锁范围。
- 向 UI 推送数据的 channel 必须有界，或者有合并机制，防止生产快于消费时内存无限增长。

## 密钥处理

- 承载密钥或明文凭据的类型实现 `Zeroize` / `ZeroizeOnDrop`，并且不实现 `Debug`，或者用手写的脱敏 `Debug`。
- 解密后的凭据只在需要的作用域内存在，不缓存进长期存活的结构。
- 错误信息不包含凭据内容。

## IPC 命令

- 每个 Tauri 命令在入口处校验参数：ID 格式、终端尺寸范围、写入数据的长度上限。
- 命令函数只做参数校验和服务调用，业务逻辑放在 crate 中。
- 返回给前端的错误是结构化的错误码加可本地化的信息，不直接透传内部错误链。
